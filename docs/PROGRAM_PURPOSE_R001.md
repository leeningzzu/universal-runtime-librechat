# Universal Runtime / Inquiry Desk — Project purpose digest

This is a navigational digest, NOT a replacement for the original SHA-locked promoted Stable Sources under docs/project_sources.

## North Star
Build a Windows-local, maintainable, multi-model AI Workbench with ChatGPT-like Project/Chat convenience plus LibreChat open provider ecosystem and Runtime-governed permission, revision, persistence, Promotion and audit. Work on ANY SUPPORTED Windows PC, not one developer's drive or login. Inquiry Desk is the current user-facing product working name; Universal Runtime is the internal control plane.

## Core and optional roles
- Core Product = ONE current LibreChat shell + Runtime Authority + shared native Project/Chat/File/Memory/Search/Artifact capabilities. ZERO user Packs must still work.
- Project = logical user workspace and long-lived chat/history/Source/Artifact hub, not a Pack, Provider, MCP session, Agent or local filesystem path.
- Provider = model access/profile only. ChatGPT consumer subscription does not supply API credentials by default.
- Runtime = Authority/governance, not UI or a duplicate database.
- Local Action Host = replaceable local read/write/process/git/test capability; read-only by default, single coherent effect approval.
- MCP = optional interoperability transport, never Authority or a hard requirement for local work.
- Domain/Universal Pack = optional reusable capability with independent version, install/activate/deactivate/uninstall and promotion lifecycles. No automatic Promotion or user activation.
- Skill = narrower repeated evidence-backed reuse; Project-specific facts remain Project Source/Memory/Artifact.

## Required user experience
New Project -> purpose once if needed -> New Chat -> direct request. Native Project Instructions, multiple Chat history, exact SAME-Project cross-Chat recall, Project-scoped Memory (distinct from user-global Memory), Files/Sources, model-understood PDF/DOCX, source-tracked RAG File Search, durable Artifacts and restart persistence. No whole-history or entire Library injection by default; storage, retrieval, injection and exact recovery are different facts.

## Mature reuse / product boundaries
Reuse LibreChat upstream first for user-facing Project, reference files, model/providers, native RAG API and pgvector. Existing Runtime/Pack next; historical mature candidates only when a real gap remains. NO custom second shell, second Chat DB, second Vector DB, generic memory/compiler, generic multi-Pack orchestrator, whole-drive Docker mount or mandatory internal proxy. Runtime controls legality of effects and release Promotion, not a competing Project UI.

## Windows portability
User sees one desktop shortcut and one Project-first interface. System prerequisites, Docker, WSL, executors, paths and ports belong in the host resolver/developer surfaces. Durable Project ID is logical. Program must eventually prove first install, restart, source preservation, data-safe update/repair/uninstall and rollback on a supported separate Windows PC.

## Governance / source
Promoted Stable Sources have one fact-class owner. Stage PASS != Product PASS != Program PASS. New Run/Stage/SHA/next action go only into transient status/handoff, not into Stable Source. Accepted baselines inherit unless bytes invalidate a specific proof family. Project Sources are preserved in their original exact user-provided text under docs/project_sources; their names/statuses/hashes must not be silently relabeled.

Shared Product baseline must be accepted before unrelated Domain Pack expansion (Academic, Novel, Regulatory, Stock). Cross-domain methods are promoted only after independent held-out evidence and explicit approval.
